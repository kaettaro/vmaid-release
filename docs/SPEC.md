# VMaid(仮称)仕様書 — MVP

最終更新: 2026-10-14
由来: tamoとClaudeの設計セッションで合意した内容。「確定」は合意済み、「提案」は実装担当が妥当性を確認して良い。

## 1. ゴール
Desktop Mate のような常駐3Dコンパニオンを、OSSとして作る。
- 3Dモデル(VRM)、モーション(VRMA)、ローカルLLMを各自が換装できる
- 会話は完全ローカル。初心者は何も入れずに動き、上級者はLLMを自由に差し替えられる
- 「放置するとダンス(dance1〜5からランダム)」のような if-then ルールを、GUIで追加できる

先行OSS(Open-LLM-VTuber, AIRI, Amica)との差別化点は、導入の軽さ・完全ローカルの既定・ルール機構。

## 2. 確定要件

| 項目 | 内容 |

## 3. 画面構成

### 3.1 キャラウィンドウ
- 枠なし・透過・最前面。キャラだけが見える
- ドラッグで移動、ホイール(またはスライダー)で拡大縮小。位置と大きさは保存
- **Shift+ドラッグでキャラの向きを変える**(横方向=左右 yaw: 右へドラッグ=画面の右向き / 縦方向=上下の傾き pitch: 下へドラッグ=頭が手前に倒れる。pitch は±75°まで、体の中心を軸に回す)。離すと45°刻みの近く±6°で吸着。向きを変えたあとの姿が窓から出ないよう、カメラの距離を自動で合わせる(窓の大きさ・位置は変えない)。向きはモデルごとに保存(`model-profiles/<ハッシュ>.json` の `yaw` / `pitch`)。表情・衣装パネルの項目・名前つきセットには含めない
- クリック透過: キャラの当たり判定外はクリックを下のアプリに通す(提案: Electronの `setIgnoreMouseEvents(true, { forward: true })` とレイキャスト/アルファ判定の組み合わせ)。ON/OFF切替あり
- **クリック = ふれあい(インタラクティブアクション)**(触った部位 — 頭・胸・お腹・腰・腕・手・脚・足と左右 — によって、ルールで反応を変えられる): 手を振る・うなずくなどのリアクション(M6からはルールの `click` トリガー)。**ダブルクリック = 会話**: 吹き出し型の入力欄が開き、返答もストリーミングで吹き出し表示
- 吹き出しの配置: キャラの頭上に「キャラのセリフ」(▽がキャラを指す)、「自分の入力」は、キャラと**PC画面全体の中央下**の間(キャラの近く)に置き、▽は画面中央下を指す(自分が画面の手前から話しかけているように見せる)。キャラが画面の右にいれば吹き出しは左下寄り・▽は左下向き、中央なら真下向き。キャラを動かすと追従する。返答中の停止は文字のない小さなアイコン(または Esc)
- 右クリック → コンテキストメニュー(表情・衣装パネルを開く / 設定を開く / クリック透過切替 / 非表示 / 終了)

### 3.2 設定ウィンドウ(別ウィンドウ)
タブ: モデル / モーション / LLM / キャラクター / 音声 / ルール / 履歴 / 表示

- モデル: VRM選択、DnD、前回モデルの復元。VRMのライセンス情報(meta)を表示し、利用条件は利用者の責任であることを明記
- モーション: VRMA / BVH の登録(1回の取り込みの上限は設定。既定は無制限)、名前付け、**タグ**による整理。取り込み時に、付けるタグ(とフォルダ名のタグ)を一斉に付与できる。一覧は、検索・タグ絞り込み・複数選択(Shift で範囲)・一括操作(登録の削除・タグの付与/解除)に対応し、数千件でも、見える行だけを描く(仮想化)。タグは userData の `motion-meta.json` に「モーション名 → タグ」で保存し、内蔵・パック・登録のすべてに付けられる(内蔵・パックが最初から持つタグは外せない)。**旧「モーショングループ」は廃止し、タグに置き換えた**(旧形式の rules.yaml・パック・取り込むルールは、自動でタグに変換する)
- LLM: 実行方式の切替(内蔵 / OpenAI互換)。内蔵ならモデルの選択・DL状況。OpenAI互換ならURL・モデル名・APIキー(任意)
- キャラクター: **複数のキャラ(モデルのパス + 名前・システムプロンプト・口調・ユーザーの呼び方)を保存・切り替え**。追加(モデルを選ぶ)・複製・削除(最後の1人は不可)・モデルの変更。右クリックメニュー/トレイの「キャラを切り替え」からも切り替えられる。「モデルを選ぶ…」で選んだ未登録のモデルは、自動でキャラとして登録される。キャラごとに分かれるもの: 話し方、会話履歴(`characterId`)、ルールの対象(`characters`)、モデルの調整値・セット・向き(モデルのハッシュごと)
- 音声: キャラが返答を声に出す(**既定オフ**)。方式は「OSの音声(`speechSynthesis`)」と「VOICEVOX 互換のローカルエンジン(ユーザーが別に起動。`POST /audio_query` → `POST /synthesis` で WAV)」。声(話者・OSの音声名・速さ・高さ)は**キャラごと**。返答のストリームを文(`。` `!` `?` 改行)で区切り、できた順に合成・再生(先読み)。中断・新しい入力で止まる。口は、再生中の音声の音量(WebAudio の `AnalyserNode` の RMS)に合わせて開閉(OSの音声は音量が取れないので、喋っている間だけ口を動かす)。通信は main が代行し、ループバックの接続先は名前解決も検証する。接続先がループバック以外のときは警告
- ルール: 6章参照
- 履歴: 保存のオン/オフ、件数・期間・サイズ、削除(すべて/○日より古い分)、エクスポート(JSON/テキスト)。再起動後も直近Nターンを文脈に使う
- 表示: 倍率、クリック透過、最前面、起動時に表示

### 3.3 トレイ
表示/非表示、設定を開く、クリック透過切替、終了。トレイ常駐(ウィンドウを閉じても終了しない)。

### 3.4 表情・衣装パネル(モーフ操作)
キャラの近くにスライダーが出て、表情や体型、衣装(の表示切替)をリアルタイムで変えられるパネル。

**方針: モデルが持っているものを自動で列挙する。** モデルごとの個別対応はしない。読み込んだVRMから次を取得してUIを自動生成する:
- 表情(VRMの `expressionManager` のプリセット + カスタム表情)→ スライダー 0〜1
- モーフターゲット(メッシュの `morphTargetDictionary` / `morphTargetInfluences`)→ スライダー 0〜1
- メッシュ/マテリアルの表示ON/OFF → トグル

UI:
- 右クリックメニューから開く。キャラに追従する小さな別ウィンドウ(キャラが動くと位置も追従)にする。キャラウィンドウに重ねるより、クリック透過との両立が楽(提案)
- 項目が多いモデル(MMD由来などで数百個)に備え、検索ボックスとグループ分け(表情 / モーフ / 表示)を付ける
- 「すべてリセット」ボタン
- 変更は即時反映

保存:
- **モデルごとのプロファイル**として保存し、次回その模型を読み込んだときに復元する
- モデルの識別はファイルのハッシュ(提案。パス変更に強い)

挙動の優先順位(提案):
- スライダーの値は「基準値」として保持する
- 自動まばたき・リップ(喋り中の口)は、該当する表情にだけ上乗せ/上書きする。ユーザーが基準を動かしても、まばたきや口パクが壊れないこと
- ルールの `setExpression` は一時的な上書きで、終了後は基準値に戻す

体型変更:
- モデルがモーフを持っていればスライダーで動かす(通常の機能)
- ボーンのスケール変更による体型変更は **実験的機能**として別トグルの裏に置く(既定OFF)。スプリングボーン(髪・服の揺れ)や当たり判定がずれる可能性があるため

衣装:
- VRMに衣装切替の規格はない。モデル側がメッシュ/マテリアルを分けていることが前提
- 初版は上記の「メッシュ/マテリアルのON/OFF」までとする。**衣装グループ**(複数のメッシュに名前を付けて「私服」「水着」のようにまとめる機能)は後続とする

## 4. アーキテクチャ(提案)

```
src/
  main/        Electron main。ウィンドウ管理、トレイ、IPC、LLMサービス、履歴ストア、モデルDL
  preload/     contextBridge。型付きIPC契約のみ公開
  renderer/
    character/ キャラウィンドウ(Three.js + three-vrm、状態機械、吹き出し)
    settings/  設定ウィンドウ(React)
  shared/      Electron非依存の純粋TS。ルールエンジン、スキーマ(zod)、型、IPC契約
```

- `contextIsolation: true`、`nodeIntegration: false`。レンダラーにNode APIを出さない
- LLMは main 側のサービスとして持ち、`LlmBackend` インターフェースで抽象化する:
  `chat(messages, opts): AsyncIterable<string>`(ストリーミング)、`abort()`
  実装は `BuiltinBackend`(node-llama-cpp)と `OpenAICompatBackend`(fetch + SSE)
- 重い推論でUIを固めないため、内蔵LLMは utility process か worker で動かすことを検討(提案)
- 状態保存は `app.getPath('userData')` 配下(7章)

### 4.1 キャラの状態機械(提案)
状態: `idle`(待機ループ) / `speaking`(喋り中) / `oneShot`(クリック反応・ルール発火の単発モーション)
- oneShot は終了後 idle に戻る
- speaking 中はルール由来のモーションを発火させない(破棄でよい)
- 常時: まばたき(VRMの `blink` 表情)。モーションとは独立に動かす

## 5. LLM

### 5.1 既定モデルの方針
条件: ①Apache 2.0 / MIT など寛容ライセンス ②ローカルで動く(一般的なノートPCで実用速度) ③日本語が使える。

| 候補 | ライセンス | 目安 | 位置づけ |
|---|---|---|---|
| **Gemma 4 E4B** | Apache 2.0 | 実効約4.5B、Q4で約5GB前後、文脈128K | **既定** |
| Qwen3 4B / 8B | Apache 2.0 | 4B〜8B | 代替。実績と情報が多い |
| Ministral 3 (3B / 8B) | Apache 2.0 | 3B〜8B | 代替。3Bは低スペック機向け |
| Llama系 | 独自ライセンス | - | 既定にしない |
| Gemma 3以前 | 独自(Gemma Terms) | - | 既定にしない(利用制限を下流に引き継ぐ義務) |

注意:
- Gemma 4 がApache 2.0であることは調査時点の情報。**実装時に公式モデルカードで必ず再確認**する(Gemma 3以前は独自規約で、集計サイトの記載が混在している)
- Gemma 4 の日本語は「E2B/E4Bは日本語精度にサイズ制約あり」との評価もある。キャラ会話の自然さはベンチマークで分からないため、**M4で同一のキャラ設定プロンプトを使い3候補を比較して既定を最終決定**する
- `node-llama-cpp` が Gemma 4 のアーキテクチャに対応しているかはバージョン依存。M4の冒頭で対応を確認し、未対応なら Qwen3 を既定にしてよい(その場合は理由を報告)
- GGUFの配布元(リポジトリ、ファイル名、SHA256、サイズ)は実装時に確認して `models.json` に記録する。この資料にはURLやハッシュを書いていない(未確認のため)

### 5.2 モデル登録(提案)
`resources/models.json` にレジストリを持つ:
`id, name, family, license, url, sha256, sizeBytes, quant, contextLength, minRamGB, notes`
アプリはこのレジストリからDL候補を表示する。ユーザーが任意のGGUFファイルを選んで使うこともできる(上級者向け)。

### 5.3 初回ダウンロード
- 同意ダイアログ(何を・どこから・何GB・以後は通信しない)を出してから開始
- 進捗表示、中断・再開、SHA256検証、失敗時の再試行
- 保存先は userData/models/。ディスク空き容量を事前チェック
- DL後は完全オフラインで動く。オフラインでも起動できること

### 5.4 プロンプト
- システムプロンプト = アプリ共通の枠 + ユーザー設定のキャラ設定
- 履歴は直近Nターンをコンテキストに入れる(Nは設定。トークン上限を超えたら古いものから落とす)
- 応答は短めを既定にする(吹き出しに収まる長さ)

## 6. ルールエンジン

### 6.1 モデル
`トリガー(いつ)→ 条件(もし)→ アクション(何をする)` の3段。複数の条件はAND。アクションは順に実行。

保存形式(YAML/JSON、zodで検証):
```yaml
version: 1
rules:
  - id: idle-dance
    enabled: true
    when:
      trigger: idle
      afterSec: 300
    if:
      - { condition: probability, value: 0.8 }
      - { condition: cooldown, sec: 600 }
    do:
      - { action: playMotion, tag: ダンス, pick: random }
```
(議論中の短縮記法 `when: idle > 300s` のような糖衣構文は、無くて良い。入れるなら読み込み時に上の形へ正規化する)

### 6.2 初版の範囲
| 種別 | 内容 |
|---|---|
| トリガー | `idle`(N秒操作なし)、`click`、`startup`、`timeOfDay`(時刻または時間帯)、`replyDone`(返答完了)、`hold`(長押し。部位・左右・押し続けた秒数 `minSec`)、`stroke`(**なでる**: ボタンを押さずに、同じ部位の上でポインタを往復。なで続けた秒数 `minSec` を変えた複数のルールで、段階的な反応にできる。1回のなでる間、各ルールは1度だけ発火)、`strokeEnd`(なで終わり)、`userMessage`(**トリガーワード**: ユーザーのチャット入力に指定の語句が含まれる/一致する。例「ダンスして」→ダンス。判定はユーザー自身の入力だけに行い、LLMの出力には行わない) |
| 条件 | `probability`、`cooldown`、`recentTouches`(直近N秒に、M回以上クリックされた。部位を指定できる)、`affection`(親密度の範囲)、`mood`(気分) |
| アクション | `playMotion`(`motion`(単体)か `tag`(そのタグが付いたモーションの中から。`pick: random` / `first`=登録順の先頭)。`durationSec`=ループ再生の秒数、`queue`=再生中なら終わってから続ける)、`setExpression`(名前、継続秒)、`applyPreset`、`wait`(秒。後ろのアクションを遅らせる。新しいふれあいが来たら、待っている分は取り消す)、`changeAffection`(親密度の増減)、`setMood`(気分を変える。秒数のあと「ふつう」に戻る)、`say`(定型セリフ。複数ならランダム) |

第2段階: ダブルクリック、ドラッグ、感情タグ検出、LLMへの発話指示、`setMorph`(モーフ/表情の基準値を変更)、`setOutfit`(衣装グループの切替。衣装グループ機能の実装後)。

`idle` の定義: クリック・ドラッグ・チャット入力がない時間。操作でリセット。1回の放置期間につき1回だけ発火(クールダウンと併用可)。

### 6.2.1 ふれあいの動作の認識(長押し・なでる)
純粋なクラス(`src/shared/touch/gesture.ts`)が、ポインタの動きから認識する。**長押し**: 押して、10px 以内でほとんど動かさず 0.6 秒以上(続く間 0.5 秒おきに通知。動かしたら、ドラッグ=移動・Shift+ドラッグ=回転なので、長押しではない)。**なでる**: ボタンを押さずに、同じ部位(`classifyTouch`)の上で、直近 1.2 秒に、往復(振れ幅 10px 以上の向きの反転)が 2 回以上、移動距離 70px 以上、速さが 40〜3000px/秒(直近 0.5 秒)のとき。0.4 秒おきに通知し、動きが 0.8 秒途切れる・部位が変わる・体から外れると、なで終わり(`strokeEnd`)。部位を指定した触れ合いのルール(または、`recentTouches` の条件があるルール)が動いたら、部位を指定しない同じ種類のルールは動かない。

### 6.2.2 気分・親密度
キャラごと(`character-state/<キャラid>.json`): `affection`(0〜100、初期30)、`mood`(`normal / happy / shy / annoyed / sleepy / sad`)、`moodUntil`、`updatedAt`。ふれあいで `changeAffection` により増減。**最後に触れ合いのあった時刻から 6 時間は減らず、そのあと 1 時間あたり 0.5 ずつ減る(下限 10)**。気分は、`setMood` の秒数のあと自動で「ふつう」に戻る。エンジンは、状態を注入された関数で読む(Electron 非依存)。

### 6.5 パック(配布用 / 私用)
パック = フォルダ(`pack.yaml`: `id` / `name` / `version` / `distribution: distributable | private` / `motions: [{name, file, source, license, redistributable, attribution, tags}]` / `rules`。パックの id は、モーションの自動タグになる。旧形式の `motionGroups` / `group` は、読み込み時にタグへ自動変換)。**どちらかは、置き場所で決まる**: 公式(配布用)= アプリの `resources/mods/official/<id>/`(自作・再配布可と確認できたものだけ。モーションに `redistributable: true` と `license` が無いとエラー。素材ファイルが入っていないことをテストで固定)、自作 = userData の `mods/individual/<id>/`、コミュニティ(取り込み)= `mods/community/<id>/`(どちらもリポジトリの外)。区分は置き場所で決まり、`distribution` は使わない(2026-10-17。ADR 0005 §8)。モーションは `<パックid>/<名前>` で登録され、パックのルール・ルールidも、同じ名前空間つきで(タグは、全モーションで共通なので、名前空間をつけない)、ユーザーの `rules.yaml` とは**別の層**として(ユーザーのルールが先に並ぶ)エンジンに合成される。ファイルは、パックのフォルダからの相対パス(`/` 区切り。`..`・絶対パス・`\`・シンボリックリンクで外へ出るもの・VRMAとして読めないものは登録しない)。**私用パックは、ルールの共有書き出し・配布ビルドに含まれない**。自分の別のPCへ移すためだけの専用の書き出し/取り込み(`.vmaidpack` = zip。取り込みは、zip slip・多すぎるファイル・展開後サイズ・想定外の種類・大文字小文字違いの重複を検査)がある。

### 6.3 定義データ駆動(重要)
トリガー・条件・アクションの種類を **定義レジストリ** として持つ:
`type, label(日本語), params: [{ name, label, kind: number|string|enum|motion|motionGroup|expression|time, min, max, default }]`
- GUIフォームはこのレジストリから自動生成する
- 種類を追加するとき、GUIを作り直さなくて済むこと
- 実行ロジックは `src/shared/rules/` に純粋関数で実装し、時刻・乱数は注入可能にしてテストする

### 6.3.1 ルールの対象キャラ
ルールには任意の `characters: [キャラのid, ...]` を書ける(省略・空 = すべてのキャラで動く)。指定があるルールは、使用中のキャラがその中にあるときだけ発火する(部位指定ルールが汎用の click ルールを抑える判定も、動いたルールだけが対象)。GUIは「対象のキャラ」のチェックボックス(キャラが2人以上のとき)。存在しないキャラidは警告(lint)。

### 6.4 ルールGUI
- 一覧: ON/OFFトグル、並べ替え、複製、削除。**検索(id・説明・タグ・動作の中身)・タグ絞り込み・有効/無効の絞り込み・複数選択(Shift で範囲)・一括操作(有効/無効・タグの付与/解除・削除)**。ルールには整理用の `tags` を付けられる(動作には影響しない)。数百〜数千件でも、見える行だけを描く
- 編集フォーム: ドロップダウンと数値入力。参照するモーション/タグは、入力しながら絞り込める欄(候補は登録済みから)で選ぶ
- モーションのタグは、設定の「モーション」タブで付ける。タグの名前を変えると、ルールの `tag:` も一緒に書き換わる
- **テスト発火ボタン**(条件を無視して今すぐ1回実行)
- YAML表示の切替(GUIと双方向同期。不正なYAMLは保存せずエラー行を表示)
- インポート/エクスポート(共有用)

## 8. プライバシー/セキュリティ
- 通信は「モデルDL」と「ユーザー設定のLLMエンドポイント」のみ。それ以外は発生させない(**例外: 音声でVOICEVOX 互換のエンジンを選んだ場合の、ユーザー設定のエンジンのアドレスへの通信。既定オフ・既定の接続先は127.0.0.1**)
- レンダラーのCSPで外部オリジンを禁止(エンドポイント通信は main 経由)
- OpenAI互換のURLは localhost 以外を設定した場合、設定画面に「外部サーバーへ会話が送信される」警告を出す
- APIキーは平文で settings.json に置かない(提案: `safeStorage`)

## 9. プラットフォーム注意
- **透過ウィンドウ/クリック透過**: Win/Macで挙動差がある。特にMac(フルスクリーンアプリ上での表示、Spaces、Dock/メニューバー)。実機確認が必要
- **Mac**: 配布には署名と公証が必要。開発中は未署名で良い。M8では手順を文書化するだけで良い
- **推論GPU**: MacはMetal、WindowsはCUDA/Vulkan(node-llama-cpp が自動選択)。GPUが無くてもCPUで動くこと
- **パッケージ**: node-llama-cpp のネイティブバイナリは asar 外に展開する設定が必要(`asarUnpack`)。Macは arm64 / x64 の扱いを決める。ビルドはMacではMac、WindowsではWindows(またはCI)で行う
- VRMの当たり判定: SkinnedMeshのレイキャストは重いので、簡易コライダ(カプセル/ボックス)かレンダーターゲットのアルファ判定を検討

## 13. Mod 中心設計(2026-10-16。`docs/adr/0005-mod-centered-design.md`)
標準機能は最小限(VRM 表示・モーション再生と管理・LLM 会話・履歴・基本のルールエンジン・表情・衣装パネル)。それ以外は、トグルで ON/OFF できる **Mod**(用語は「Mod」に統一。旧「拡張」「パック」)。
- 形態: データ Mod(コードなし・通信なし)/ 公式の機能 Mod(本体同梱・ON のときだけ遅延ロード)/ スクリプト Mod(「開発者向け」トグル ON のときだけ。M15)。
- 公式の機能 Mod: モーションのタグ・足の接地補正・音声合成・親密度と気分・高度な触れ合い(M10)、MMD 対応(M12)、FBX・PMX/X インポーター(M14)。公式のデータ Mod: ダンス・おっとり・元気・クール・ヤンデレ(M11)。
- OFF は即解除でデータは消さない。Mod のルール定義(ノード・パラメータ)は、提供元の Mod が OFF のとき「未解決」として保持され、実行されない(ADR 0003 とその補遺)。
- マニフェストは `mod.yaml`(旧 `pack.yaml` も読める)。`requires` に、使う機能 Mod を書く。Mod は `.vmaidmod`(zip)で書き出し・取り込み。取り込み時に中身を確認し、追加直後は OFF。
- スロット: Mod は `slots:`(id・表示名・種類 motion/text)を宣言し、ルールの `{{slot:id}}` で使う。利用者が、「Mod」タブで、モーション名などを選ぶ(値は設定の `mods.slots`)。空のままなら、その反応は動かない。素材を含めずに、反応の枠だけを配れる(性格 Mod のクリック・放置のモーションが、この方式)。
- 初回の移行: 以前から使っていた機能に対応する Mod を ON にする(動作を変えない)。新規インストールは、すべて OFF。
- **状態・感情・小道具(M13)**: 公式の機能 Mod「状態と感情」(`emotion-state`)と「小道具」(`props`)。ルールに、条件 `state` / `emotion`、アクション `startState` / `endState` / `setEmotion` / `changeEmotion` / `showProp` / `hideProp`、トリガー `emotionTag`(AI の返答の `[emotion:名前]`)が増える。状態は自由な名前で、実行中だけ(再起動で消える)。感情値は 0〜100 で、キャラごとに保存し、1分に 1 ずつ 0 に減る。小道具は、Mod の `props:`(id・.glb・付ける骨・大きさ・ずれ・向き)で宣言し、骨の子として付く(VRM の人体ボーン名、MMD は対応するボーンに)。GLB は、1ファイルで完結したもの(外部ファイル・URL への参照があるものは読まない)。Mod のルールが出した効果(状態・小道具・表情の上書き)には、その Mod の id(source)が付き、Mod を OFF にすると、すぐ解除される。
- **形式インポーター(M14)**: 公式の機能 Mod「FBX インポーター」(`fbx-import`)と「PMX インポーター(小道具)」(`pmx-import`)。ON のときだけ、読み込み用のコードを使う。
  - FBX のモーション(Mixamo など)は、取り込み時に VRMA へ変換する: FBX の骨格を時間ごとにサンプリング → BVH の形に直す(`skeletonToBvh`)→ BVH と同じ経路(向き・単位・足元の補正、VRM ボーンへの対応)→ VRMA。再生側は VRMA のまま。
  - 小道具(`props:`)は、.glb(標準)に加えて、.fbx(FBX インポーター)・.pmx(PMX インポーター)を指定できる。FBX は、外部の画像・URL を読まない。PMX は、Mod のフォルダの中の画像を、専用プロトコル経由で読み、物の中心を骨に合わせて付ける(位置は `position` で調整)。単位は、形式ごとに、メートルにそろえる(glb: m、fbx: cm、pmx: MMD の 1 単位 ≈ 8cm)。
  - `.x`(DirectX)形式は、寛容ライセンスの three 用ローダーを確認できなかったため、未対応(未確認)。
- **スクリプト Mod(M15。ADR 0002)**: Mod の `mod.yaml` に `script:`(`entry`・`apiVersion: 1`・`permissions`・`contributes`)を書くと、JavaScript で、ルールのアクション・トリガーを足せる。
  - **「開発者向け」が ON のときだけ**、取り込み・使用できる(既定 OFF)。配布用(公式)の Mod には、スクリプトを含められない。取り込み・ON のたびに、権限を日本語で列挙して確認する(外部への通信は、赤い警告)。追加直後は OFF。
  - 実行環境: Mod ごとに、非表示の BrowserWindow(sandbox・contextIsolation・専用 partition)。ファイルは専用プロトコル `vmaid-ext://<Mod の id>/…`(Mod のフォルダの中の .js だけ)。CSP でネットワーク等を遮断(unsafe-eval なし)。WebRTC は、ポリシーと API の削除の両方で止める。窓の識別は main が窓から決める。起動は遅延で、使われなければ 5 分で終了する。
  - ホスト API(`host`): `log` / `onAction(fn)` / `http.fetch`(宣言したオリジンへの完全一致だけ。main が代行。リダイレクト不追従・サイズと時間の上限・接続時にループバックを確認)/ `storage.get,set`(Mod ごとに 256KB まで)/ `motion.add,play,remove`(追加できるのは検査済みの VRMA だけ。名前は `<Mod の id>/<名前>`。消せるのは自分が足したものだけ)/ `say` / `rules.emit`(宣言したトリガーだけ)。権限は、宣言して承認したものだけ。1秒に 20 回までの制限。
  - ルールには、`contributes` で宣言した種類が、`<Mod の id>/<種類>`(Mod の中のルールでは、ローカル名でも書ける)で増え、フォームは宣言から自動で作られる。Mod が OFF・開発者向けが OFF のときは、未解決として保持され、実行されない。
  - 通信ログ(本文は残さない)とログは、「Mod」タブで見られる。限界: CPU を使い続けるスクリプトによる妨害は、防げない(信頼できる配布元のものだけを入れる)。
- **モーション生成 Mod(M16。ADR 0001)**: `examples/mods/motion-gen-textvrma/`(スクリプト Mod。アプリには同梱しない)。「モーション生成: 手を振る」の入力で、ローカルの text-to-vrma(`POST /v1/motions`。固定で `engine: ardy`・`planner: none`・`use_jev: false`・`format: vrma`)に頼み、できた VRMA を `host.motion.add` で一覧に足して再生する。同じ説明・長さはキャッシュ(作り直さない)、生成は同時に 1 件・待ちは 3 件・開始の間隔 10 秒、できた動きは 40 件まで。トークン・接続先は、Mod の設定(secret は暗号化)。導入は `docs/guides/motion-gen-setup.md`。
- **スクリプト Mod の設定項目**: `script.settings`(`string` / `secret` / `number` / `boolean`)を、「Mod」タブで入力し、スクリプトは `host.settings.get(名前)` で読む。secret は safeStorage で暗号化して保存し、画面に値を出さない。
- **緊急リセット**(2026-10-17。旧「効果を今すぐ解除」を置き換え): ホットキー Ctrl+Alt+Shift+R(Mac は Cmd+Option+Shift+R。基本設定で変更可)・トレイ・右クリックメニューで、キャラを初期の表示(表示・主画面の右下・倍率 1・クリック透過 OFF)に戻し、向き・再生中のモーション・ルールの効果(状態・感情値・小道具・表情の上書き・待っているアクション・画面効果・ゲーム・BGM)・重ねた表情・衣装セットを初期に戻す。Mod の ON/OFF と、保存したデータは変えない。
- 公式のリポジトリ・本体には、成人向けのモーション・指示文と、催眠 Mod を同梱しない(催眠のような、状態・小道具・表情を使う Mod の枠組みだけを提供する)。
