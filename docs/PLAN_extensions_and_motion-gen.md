1. 着手前に `CLAUDE.md`・`docs/SPEC.md`・この計画書を読む。
2. **まず P0(調査・設計)だけを行い、ADR(設計判断の記録)3本をユーザーに見せて承認を得る。** 承認前に P1 以降のコードを書かない。
3. 各フェーズの終わりに「ユーザー確認」の関門がある。確認が取れてから次へ進む。
4. 「(要確認)」は計画時点の推測。実装時にコードや公式文書で確認し、結果を ADR / ドキュメントに残す。確認できなければ「未確認」と書く。
5. 着手時に `git status` を見る。**未コミットの変更が多数ある**(2026-10-15 時点で約30ファイル)。混ぜないよう、先にユーザーに確認して整理(コミットまたは退避)し、作業ブランチ(例 `feat/extensions`)を切る。

## 1. ゴールと範囲

### ゴール
- **A. 拡張(mod)基盤**: 機能を「オプションの拡張」として後から足せる。**他のユーザーも拡張を作って、導入できる。**
- **B. 最初の拡張「モーション生成」**: ユーザーの入力に合わせて、モーションを取れる(外部ツール text-to-vrma を、ユーザーが別に導入して連携する。**上級者向けのオプション**)。
- **C. ドキュメント**: 連携ツールの**導入説明書**と、**拡張の作り方ガイド**。

### 完成の定義(シナリオ)
1. (上級者) text-to-vrma を、説明書どおりに導入する。ARDYモード・AIなし・Jev無効 = 完全ローカル。
2. VMaid の「設定 → 拡張」でモーション生成をONにする。必要な権限(接続先 localhost のみ)が表示され、承認する。
3. 設定画面で「手を振りながら歩く」と入力して生成 → キャラで試し再生 → 採用すると、モーション一覧に入り、ルールのグループにも使える。
4. ルールで「トリガーワード『モーション:』を含む入力 → その続きの文でモーション生成して再生」を作る。チャットで `モーション: ゆっくりお辞儀して` と入力すると、生成中は待機し、できたら再生される。**同じ入力の2回目は、生成せず即再生される**(キャッシュ)。
5. ネットワークを切っても、本体は普通に動く。拡張も、接続先がlocalhostなら動く。
6. 第三者が、作り方ガイドとサンプルだけで、簡単な拡張を作って動かせる。

### 非ゴール(今回やらない)
- 拡張の配布ストア・検索・自動更新(外部通信しない方針に反する)
- 拡張コードの審査・署名制度(将来の課題)
- ネイティブコード・外部プロセスを起動する拡張(Tier 3。4.1参照)
- text-to-vrma / ARDY / Llama / FuguMT のコードやモデルの**同梱・自動ダウンロード**
- キャラの返答中にAIが `[motion: …]` を出して生成する機能(感情タグと同じく MVP 外。将来拡張の候補)
- 拡張が独自UIを自由に描くこと(v1 は宣言的なフォームのみ)
- VMD取り込み(`docs/MMD_FEASIBILITY.md` の決定を維持。将来「モーション取り込み拡張」を第三者が作れる余地は残す)

## 2. 守ること(不変条件)
既存の `CLAUDE.md` に加えて、この計画で特に守る。

1. **本体は外部通信しない。** 拡張が通信する場合も、manifestで宣言し、ユーザーが承認した接続先だけ。通信は**必ず本体(main)のゲートを通す**。拡張のコードが直接ネットワークに出られる経路を作らない。
2. **最小権限。** 権限チェックを通らないホストAPIの経路を作らない。拡張は既定でOFF。
3. **ルールのアクションは「モーション・表情・セット・セリフ」だけ**という既存の安全の前提(`rulesActions.ts` の取り込み確認文)を壊さない。拡張が足すアクションは、拡張名つきで見え、**ファイル操作・プロセス起動のアクションは作らない**。
4. **ルールのYAMLは、拡張が無い環境でも壊れない。** 未導入・無効の拡張のアクションを含むルールが、ファイル全体の不正扱い(いまのルールが適用されなくなる)にならないこと。YAMLを往復しても、そのノードが消えないこと。
5. **外部ツールのコード・モデルを同梱しない。** text-to-vrma のコードを流用する場合は MIT の著作権表示を `THIRD_PARTY_LICENSES.md` に入れる(原則は流用せず、自前で書く)。
6. **本体の軽さを保つ。** 拡張を使わない人の起動時間・メモリを増やさない(拡張ランタイムは遅延ロード)。
7. 純粋ロジックは `src/shared/` に置いて Vitest で試す。Win/Mac 両対応。実機でしか確認できない点は `docs/MANUAL_TEST.md` に書く。
8. 外部ツールの仕様(API・コマンド・ライセンス)は、推測で書かず、取得したソースで確認する。

## 4. 拡張(mod)基盤の設計(提案。P0で検証して確定)

### 4.1 拡張の3つの階層
| 階層 | 中身 | リスク | v1 |
|---|---|---|---|
| **Tier 1 データパック** | ルール・モーショングループ・キャラ設定・(権利の明らかな)モーション等の**データだけ** | 低(コードが動かない) | 対応 |
| **Tier 2 スクリプト拡張** | JavaScript。**サンドボックスの中**で動き、ホストAPIだけ使える | 中 | 対応(実験的API) |
| Tier 3 ネイティブ/プロセス起動 | OSのコマンド実行、任意のファイルアクセス | 高 | **対応しない** |

外部ツール(text-to-vrma など)は、**ユーザーが自分で起動**し、拡張は localhost のHTTPで話しかけるだけ。VMaidがプロセスを起動しない。

### 4.2 パッケージ形式とmanifest
- 形式: フォルダ、または zip(拡張子 `.vmaidext`)。ルートに `vmaid-extension.json`。
- 識別子: `id`(`^[a-z0-9][a-z0-9-]{2,40}$`)、`version`(semver)、`apiVersion`(整数)、`name`、`description`、`author`、`license`(SPDX)。
- 例(形のみ。項目名は P0 で確定):
```json
{
  "id": "motion-gen-textvrma",
  "name": "モーション生成(text-to-vrma連携)",
  "version": "0.1.0",
  "apiVersion": 1,
  "license": "MIT",
  "entry": "main.js",
  "activation": "onDemand",
  "permissions": {
    "network": ["http://127.0.0.1:<port>"],
    "motion": ["add", "play"]
  },
  "contributes": {
    "actions": [
      {
        "type": "generateMotion",
        "label": "モーションを生成して再生",
        "params": [
          { "name": "prompt", "label": "動きの説明", "kind": "string", "required": true, "template": true },
          { "name": "durationSec", "label": "長さ(秒)", "kind": "number", "min": 1, "max": 30, "default": 4 }
        ]
      }
    ],
    "settings": [
      { "name": "endpoint", "label": "接続先", "kind": "string", "default": "http://127.0.0.1:<port>" },
      { "name": "token", "label": "トークン(必要な場合)", "kind": "secret" }
    ]
  }
}
```
- `contributes.actions` の中身は、既存の `NodeDef`(`definitions.ts`)と**同じ形のデータ**にする。ルールGUIのフォームは、いまと同じ仕組みで自動生成される。`template: true` は「`{{message}}` 等の変数を使える」の意味。
- manifest は zod で厳密に検証する。未知の項目は無視、不正なら読み込まない。

### 4.3 拡張ポイント(v1)
1. **ルールのアクション**(`contributes.actions`): 上記。
2. **ルールのトリガー**(`contributes.triggers`): 拡張が `host.rules.emit(...)` でイベントを起こす。**条件(condition)の拡張は v2**(エンジンが同期で評価するため)。
3. **設定フォーム**(`contributes.settings` と宣言的パネル): 入力欄・数値・選択・チェック・`secret`(暗号化して保存)・ボタン(コマンド)・状態表示。独自HTMLは描かせない。
4. **モーションの登録**: ホストAPI経由で、検査済みVRMAを本体のモーション一覧に追加できる。
- **アクションは非同期で、完了を待たない**(v1)。同じルールの後続アクションは、完了を待たずに実行される。「生成→再生」は、拡張のアクションの中で完結させる。

### 4.4 ホストAPI(apiVersion 1。権限ごとに許可)
| API | 権限 | 内容 |
|---|---|---|
| `host.log(level, msg)` | なし | 拡張ごとのログ(設定画面で見える) |
| `host.settings.get() / onChange` | なし | 自分の設定を読む。`secret` は復号して渡す |
| `host.storage.read/write` | `storage` | 拡張専用のデータ領域。総量に上限 |
| `host.http.fetch(url, init)` | `network` | **mainが代行して通信**。宣言した接続先だけ(4.7) |
| `host.motion.add(name, vrma)` | `motion:add` | 検査(`checkVrmaBytes`・上限)を通して一覧に追加。名前衝突は既存の規則 |
| `host.motion.play(nameOrBytes)` | `motion:play` | 登録名、または一時再生(登録しない) |
| `host.motion.remove(name)` | `motion:add` | **自分が追加したもの**だけ |
| `host.say(text)` | `character:say` | 吹き出しにセリフ |
| `host.rules.emit(type, payload)` | `rules:emit` | 拡張のトリガーを発火 |
| `host.events.on('userMessage' \| …)` | `events:userMessage` など | **入力文を読む権限。承認画面で目立たせる。** 通常は不要(下記) |
- 最小権限の考え方: アクションは、ルールが展開した**パラメータだけ**を受け取る。モーション生成拡張は、ユーザーの入力文を読む権限を**持たない**(`{{message}}` は本体が展開して渡す)。
- 拡張の識別は、**mainが「どのウィンドウから来たか」で決める**。拡張が名乗った `id` を信用しない。

### 4.5 実行方式(提案。P0でPoCして確定)
- 拡張ごとに**非表示の `BrowserWindow`**(`sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`)を、**専用の `session.fromPartition('ext-<id>')`** で作る。
- 拡張のファイルは、本体が登録する**専用プロトコル**(例 `vmaid-ext://<id>/…`)で配信する。HTMLは本体が生成し、拡張にHTMLを持たせない。
- CSP: `default-src 'none'; script-src vmaid-ext://<id>; connect-src 'none'`(`unsafe-eval` なし)。**拡張のコードはネットワークに直接出られない。** 通信は `host.http.fetch` だけ。
- 拡張ウィンドウ用のpreloadは、許可リスト方式のメッセージ送受信だけを公開する。
- 起動は遅延(`activation: onDemand` が既定)。しばらく使われなければ終了。クラッシュ・無限ループは、タイムアウトで本体と切り離す。
- 比較検討の対象: `utilityProcess`(Node。サンドボックスにならないため**不採用の想定**)。PoCでメモリ・起動時間を macOS / Windows で測る。

### 4.6 ルールエンジン側の変更(コア)
- **レジストリ化**: `RuleRegistry`(トリガー・条件・アクションの定義の集合)を作り、`schema.ts` / `edit.ts` / `lint.ts` / `engine.ts` / 設定UIが**引数やコンテキストで受け取る**。既定は内蔵の定義のみ(いまと同じ動き)。既存のテスト(`rules.test.ts` など)は、すべて緑のまま。
- **未解決ノード**: レジストリに無い種類は、エラーにせず「未解決」として保持する。エンジンはそのルールを実行しない。GUIは「拡張『xxx』が必要です」と出す。YAMLを読み書きしても、**ノードの中身を失わない**(往復テストを書く)。
- **変数展開**: 入力文トリガー(`userMessage`)のイベントに対し、`template: true` のパラメータ内の `{{message}}`(入力全体)と `{{rest}}`(一致した言葉より後ろ。`equals` のときは空)を展開する。**`say` にも使える**汎用機能にする(例: `「{{message}}」って言ったね`)。
- **`ActionRequest` に追加**: `{ kind: 'extension', extensionId, action, params, ruleId }`。
- ルールの**テスト発火**・**取り込み**(`importRules`)でも、拡張アクションが正しく扱われること。

### 4.7 セキュリティ要件(必須)
1. 拡張は**既定OFF**。有効化の前に、権限を**日本語で列挙した確認**を出す。更新で権限が増えたら再確認。
2. **ネットワーク**: `host.http.fetch` は main が実行。接続先は manifest で宣言し承認された**オリジン(スキーム+ホスト+ポート)と完全一致**のみ(前方一致・サブドメイン一致は不可)。リダイレクトは別オリジンへ追従しない。`localhost` 宣言でも、名前解決の結果が**ループバックでなければ拒否**(DNSリバインディング対策。`localhost.evil.example` のような名前を拒否するテスト)。メソッド・本文サイズ・応答サイズ・タイムアウトに上限。
3. 接続先が**localhost以外**の拡張は、承認画面と設定画面に「会話や入力が外部に送られる可能性があります」と**赤い警告**を出す。
4. 拡張ごとの**通信ログ**(時刻・URL(本文は除く)・結果)を、設定画面で見られる。
5. ファイル・OS・プロセスには**触れられない**(サンドボックス)。データは `host.storage` のみ。
6. **インストール時**: zip展開のパストラバーサル(zip slip)・シンボリックリンク・展開後サイズ爆弾・ファイル数上限を検査。`id` と `entry` を検証。
7. 拡張由来の文字列は、必ずテキストとして表示(`innerHTML` 禁止)。IPCは許可リスト+入力検証(zod)+サイズ上限。
8. **外部(本体に同梱でない)拡張のインストールは、「開発者向け: 外部の拡張を許可」をONにしたときだけ**(既定OFF。なりすましの配布を避けるため)。内蔵の公式拡張は、この設定に関わらず使える。
9. 限界の明記: サンドボックスでも、CPU消費による妨害などは完全には防げない。導入時に「信頼できる配布元のものだけを入れてください」と表示する。

### 4.8 UI(設定 → 「拡張」タブ)
- 一覧(名前・版・作者・ライセンス・状態)、ON/OFF、権限の表示、削除、拡張ごとの設定フォーム、通信ログ。
- インストールは**ファイル選択ダイアログ**(フォルダ/`.vmaidext`)。ドラッグ&ドロップは使わない(透過ウィンドウでの不具合の前例)。
- ルールGUIでは、拡張由来のノードに**拡張名のバッジ**を付ける。

### 4.9 バージョニング
- `apiVersion` は整数。非互換な変更で上げ、**直前の版までは動かし続ける**。v1 は「実験的」と明記(変わりうる)。
- 本体が対応しない `apiVersion` の拡張は、読み込まずに理由を表示する。

## 5. 最初の拡張: モーション生成(`motion-gen-textvrma`)

### 5.1 置き場所と配布
- 本体のリポジトリの `extensions/motion-gen-textvrma/` に置く**公式の内蔵拡張**。**既定OFF**。自前のコードだけで、第三者のコード・モデルは含まない。
- 外部ツール(text-to-vrma)は**ユーザーが別に導入**する。VMaid は同梱も自動ダウンロードもしない。

### 5.2 「ユーザーの入力に合わせてモーションを取る」の具体像
| 経路 | 内容 | 本計画 |
|---|---|---|
| G1 手動 | 拡張の設定パネルで、動きの説明・長さ・ループを入力 → 生成 → **キャラで試し再生** → 「採用」(一覧に登録、名前・グループを付ける)/ 破棄 | 作る |
| G2 ルール | アクション `generateMotion`。トリガー `userMessage` と組み合わせ、`{{rest}}` や `{{message}}` を説明文にする | 作る |
| G3 AI連動 | キャラの返答中に、AIが動きを指示して生成 | **作らない**(将来) |

- G2 の初期ルール例(プリセット): トリガーワード「モーション:」(`passToLlm: false`)→ `generateMotion`(prompt = `{{rest}}`、再生する)。**拡張が有効なときだけ**使えるルールとして提供する(無効なら未解決表示)。

### 5.3 振る舞いの規則
- **待ち時間**: 生成は秒〜分かかる。生成中は待機モーションのまま、吹き出しに「考え中…」(`host.say`)を出す。完了で再生。失敗・タイムアウトは、短い日本語の理由を出す。
- **キュー**: 同時実行は1件。待ち行列は最大3件、超えたら破棄して通知。**キャンセル**できる(設定パネルのボタン、新しい生成の指示)。
- **再生のタイミング**: 会話中(`speaking`)にできあがったら、会話が終わってから再生(最大60秒待つ。過ぎたら登録のみ)。ルール由来のモーションは喋り中に捨てる既存仕様(SPEC 4.1)と矛盾させない。
- **キャッシュ**: キー = ハッシュ(接続先の種類・正規化した説明文・長さ・ループ・生成パラメータ)。拡張のデータ領域に `generated/<hash>.vrma` と `index.json`(説明文・作成日時・パラメータ)。**ヒットすれば通信せず即再生**。上限(例: 200件または1GB)を超えたら古い順に削除。
- **一時再生と採用**: ルール経由の生成物は、まずキャッシュに入れて**一時再生**する(一覧を汚さない)。「採用」で初めて本体のモーション一覧に登録する(名前は `gen-<要約>-<4桁>` など。衝突は既存規則)。
- **入力の制限**: 説明文は最大500文字(超過は切らずにエラー)。連続生成にクールダウン(既定10秒)。
- **安全**: 生成結果は、必ず `checkVrmaBytes` と上限(30MB)を通す。不正なら捨てる。

### 5.4 text-to-vrma との接続(アダプター)
- インターフェース(拡張の内部):
```ts
interface MotionBackend {
  health(): Promise<{ ok: boolean; version?: string; detail?: string }>
  generate(req: { prompt: string; durationSec?: number; loop?: boolean }, signal: AbortSignal,
           onProgress?: (p: number) => void): Promise<{ vrma: Uint8Array; meta?: unknown }>
}
```
- **P0で、text-to-vrma のローカルAPIの仕様を、取得したソースで確認する**: README の HTTP API の節、`tools/api-server.mjs`、`docs/`、ARDYエンジン(`tools/ardy-engine/server.py`。localhost:2337 の `/health` `/progress` `/generate` `/generate-stream` を確認済み)。**確認すること**: 「テキスト → `.vrma`」を返す経路があるか(あるのは motion spec JSON までか)、認証(READMEに**Host/Origin/トークン検証**の記述あり)の方式、応答の形式、エラー、進捗、キャンセル、バージョン取得。**エンドポイント名や応答を推測で書かない。**
- 判断の分岐(P0のADRで決める):
  - (a) APIが `.vrma` を返す → そのまま使う。
  - (b) spec JSON までしか返さない → `.vrma` への変換を自前で実装する(text-to-vrma の MIT コードを**参考**にする場合は著作権表示を入れる)か、(c) へ。
  - (c) APIが不安定/不十分 → 拡張は**フォルダ監視取り込み**(ユーザーが text-to-vrma 側で作った `.vrma` を、指定フォルダに置くと自動で取り込む)に縮小。G2(入力に合わせた生成)は後回しにする。
- アダプターは**薄く**作る。APIは「実験的」とされているので、バージョンを取得して**未検証の版なら警告**(失敗にはしない)。**モックサーバー**(確認した仕様を再現)を `test/` に用意し、実ツール無しで契約テストを動かす。
- **プライバシー表示**: 設定パネルに接続先の種類(ローカル/外部)を表示。ループバック以外なら赤い警告と明示の確認。text-to-vrma 側の設定(ARDY・AIなし・Jev無効)は VMaid から制御できないので、導入説明書への案内を出す。
